# План выполнения и обучения: приватные матчи Dota 2

Дата: 12 октября 2026 года. Предлагаемый порядок работ; реализация ещё не начата.

## Результат первой версии

Сайт для своей группы: импорт приватного матча через координатор или загрузку демки, история матчей, подробности матча, статистика участников. Владелец пишет бэкенд на Go; Codex делает фронтенд. Предлагаемая база — PostgreSQL. HTTP API начинаем на net/http; выбор фронтенд-стека фиксируем при согласовании интерфейса.

Источники данных проверяются экспериментально. Наличие сообщений в protobuf-схемах не гарантирует, что текущий координатор ответит на запрос или заполнит все показатели.

## 1. Подготовить основу Go

Изучить: функции, указатели, структуры, срезы, map, методы, error, defer, пакеты и модули. Уже знакомые темы можно пропустить.

- [Руководство Go](https://metanit.com/go/tutorial/)
- [Структуры](https://metanit.com/go/tutorial/4.2.php)
- [Срезы](https://metanit.com/go/tutorial/2.13.php)
- [Модули](https://metanit.com/go/tutorial/5.2.php)
- [Тип error](https://metanit.com/go/tutorial/11.2.php)

Ты: создать отдельный модуль проекта, описать учебные Match и MatchPlayer, собрать пример из десяти игроков. Не связывать модель сайта напрямую с типами библиотеки координатора.

Я: уточнить состав страниц — история, матч, участник, импорт.

Критерий: программа собирается, хранит пример матча в структурах и корректно обрабатывает ошибку.

## 2. Поднять HTTP API с тестовым матчем

Изучить: обработчики, маршруты, GET/POST, коды ответов, query-параметры, JSON и проверку входных данных.

- [Первое веб-приложение](https://metanit.com/go/web/1.1.php)
- [Маршрутизация](https://metanit.com/go/web/1.2.php)
- [Веб-программирование на Go](https://metanit.com/go/web/)
- [encoding/json — документация Go](https://pkg.go.dev/encoding/json)

Ты: сделать GET /api/health, GET /api/matches, GET /api/matches/{id} на тестовых данных. Вернуть JSON, 404 для отсутствующего матча и 400 для неверного параметра. В учебнике METANIT веб-примеры датированы 2018 годом; использовать их для основ, детали текущего API сверять с документацией Go.

Вместе: согласовать названия полей, единицы измерения, nullable-показатели, формат даты и ошибок. Внешние 64-битные идентификаторы передавать фронтенду строками. Зафиксировать примеры ответов в docs/api.md.

Я: после согласования контракта начать страницу матча и историю на тестовых ответах.

Критерий: браузер получает JSON; фронтенд и бэкенд используют один контракт.

## 3. Проверить координатор отдельной утилитой

Изучить: интерфейсы, события, горутины, каналы, protobuf, контекст и таймауты.

- [Интерфейсы](https://metanit.com/go/tutorial/6.1.php)
- [Горутины](https://metanit.com/go/tutorial/7.1.php)
- [Каналы](https://metanit.com/go/tutorial/7.2.php)
- [context — документация Go](https://pkg.go.dev/context)
- [go-dota2](https://github.com/paralin/go-dota2)
- [Сообщения истории и подробностей матча](https://github.com/paralin/go-dota2/blob/master/protocol/dota_gcmessages_client.proto)
- [Пример запросов в ValvePython/dota2](https://github.com/ValvePython/dota2/blob/master/dota2/features/match.py)

Ты:
1. Авторизоваться в Steam и дождаться готовности сессии GC.
2. Проверить CMsgGCMatchDetailsRequest для известного ID своего приватного матча.
3. Проверить CMsgDOTAGetPlayerMatchHistory с include_practice_matches=true.
4. Выяснить актуальные ID сообщений и механизм соответствия запросов ответам для выбранной версии библиотеки.
5. Сохранить обезличенный пример ответа, проверить result и наличие полей.
6. Описать фактически доступные показатели и поведение при таймауте.

Готовые обёртки не предполагаются: может потребоваться адаптер поверх низкоуровневых запросов. Учётные данные остаются на сервере и не попадают в примеры ответов или репозиторий.

Я: скорректировать таблицу матча по реальным данным.

Критерий: получен настоящий матч либо документирован результат проверки и выбран путь через демки для первого сквозного сценария.

## 4. Сохранить матчи в PostgreSQL

Изучить: таблицы, типы данных, первичные и внешние ключи, UNIQUE, INSERT, SELECT, JOIN, транзакции и параметризованные запросы.

- [PostgreSQL на METANIT](https://metanit.com/sql/postgresql/) — главы 2, 3 и 6
- [Работа с БД в Go](https://metanit.com/go/tutorial/10.1.php)
- [PostgreSQL в Go](https://metanit.com/go/tutorial/10.3.php)

Ты: подготовить миграции и таблицы matches, players, match_players, import_jobs. Отдельно хранить происхождение данных; запись матча и игроков сохранять атомарно. Согласовать ключи и правила объединения источников. При отсутствии надёжного идентификатора не объединять матчи по догадке.

Я: подключить настоящий API истории и страницы матча.

Критерий: данные переживают перезапуск; повторный импорт известного матча не создаёт дубль; матч не сохраняется наполовину при ошибке.

## 5. Разобрать демку локально

Изучить: Reader/Writer, открытие и чтение файлов, callbacks, преобразование данных парсера в собственную модель.

- [Чтение и запись файлов](https://metanit.com/go/tutorial/8.3.php)
- [Manta — Go-парсер демок](https://github.com/dotabuff/manta)

Ты: отдельной утилитой разобрать одну свежую .dem, получить доступные идентификаторы, результат и показатели игроков. Manta выдаёт низкоуровневые данные; итоговую модель нужно собрать самостоятельно. По возможности сравнить с координатором и игровым экраном результатов.

Вместе: определить поля, которыми демка дополняет матч, и правила конфликта источников.

Критерий: демка преобразуется в ту же модель матча, которую понимает сайт; повреждённый файл даёт контролируемую ошибку.

## 6. Добавить загрузку и фоновые задания

Изучить: загрузку файлов по HTTP, goroutines/channels, ограничение параллелизма и состояния задания. Конкретные средства загрузки смотреть в документации net/http.

- [Веб-программирование Go](https://metanit.com/go/web/)
- [Горутины](https://metanit.com/go/tutorial/7.1.php)
- [Каналы](https://metanit.com/go/tutorial/7.2.php)

Ты: реализовать POST /api/imports/replay, POST /api/imports/gc и GET /api/imports/{id}. Длительная обработка выполняется вне HTTP-запроса. Состояния: queued, processing, completed, failed. Возвращать ID задания, затем ID матча или ошибку. Ограничить размер файла и число одновременных обработок. После перезапуска незавершённые задания не должны навсегда оставаться processing.

Я: сделать форму импорта, прогресс загрузки, отображение статуса обработки, повторную попытку и переход к матчу. На MVP достаточно опроса статуса.

Критерий: пользователь добавляет матч из браузера; видит завершение или понятную ошибку; повторная отправка не создаёт дубли.

## 7. Сделать статистику группы

Изучить: GROUP BY, COUNT, SUM, AVG, JOIN, ORDER BY, LIMIT/OFFSET.

- [PostgreSQL](https://metanit.com/sql/postgresql/) — главы 4 и 6

Ты: реализовать GET /api/players и GET /api/players/{id}; считать игры, победы, поражения, винрейт, средние kills/deaths/assists. Статистика считается только по добавленным завершённым матчам группы. Неполные данные не превращаются в нули; каждый показатель имеет понятную выборку. KDA-ratio, если потребуется, согласовать отдельно от средних K/D/A.

Я: сделать таблицу участников, страницу игрока, фильтры и сортировку. Показать период и количество матчей.

Критерий: расчёты совпадают с ручной проверкой нескольких матчей, в том числе при смене игроком стороны.

## 8. Проверить и запустить

Ты: подготовить конфигурацию, логирование, серверные таймауты, доступ группы, право импорта, резервную копию базы и правила хранения демок. Настроить размещение и HTTPS.

Я: проверить телефон и компьютер, длинные ники, пустые экраны, неполные данные, ошибки API и подготовить сборку.

Вместе: проверить реальный импорт, повторный импорт, неверный ID, повреждённую демку, отсутствие координатора, перезапуск во время задания и восстановление данных.

Критерий: друг открывает сайт, смотрит матч и статистику; авторизованный участник добавляет матч; история сохраняется после перезапуска.

## Что нужно понимать про фронтенд

Реализацию выполняет Codex. Владельцу достаточно понимать связь браузера с API:

- [HTML и CSS](https://metanit.com/web/html5/) — страницы, таблицы и формы
- [fetch](https://metanit.com/web/javascript/20.1.php) — запросы к твоему серверу и обработка ответа

Глубокое изучение фронтенд-фреймворка не является условием выполнения бэкенда.

## Порядок обучения

Go → HTTP/JSON → проверка координатора → SQL и хранение → файлы и Manta → фоновые задания → агрегаты → запуск.

Учить тему перед соответствующей задачей и закреплять работающим результатом. Первое задание: учебный Match с десятью игроками и GET /api/matches/{id}, возвращающий JSON. Первый рубеж продукта: один реальный приватный матч отображается на сайте.
