# Навигация по проекту Dota Stats

Этот файл связывает учебный план с предложенной структурой проекта.

- [PROJECT_PLAN.md](PROJECT_PLAN.md) — что изучать и делать, порядок этапов и критерии готовности.
- [PROJECT_STRUCTURE.md](PROJECT_STRUCTURE.md) — где размещать реализацию и за что отвечает каждый файл и пакет.

План определяет порядок работы, а структура помогает выбрать место для кода. Перечисленные ниже пути относятся к предлагаемой архитектуре и не означают, что эти файлы уже созданы.

## Этапы плана и соответствующие части проекта

| Этап из PROJECT_PLAN.md | Где размещать результат по PROJECT_STRUCTURE.md | Критерий перехода дальше |
| --- | --- | --- |
| 1. Подготовить основу Go | `../go.mod`, `internal/domain/match.go`; учебный пример можно начать в `main.go` | Программа собирается, содержит матч с десятью игроками и обрабатывает ошибку. |
| 2. Поднять HTTP API с тестовым матчем | `../cmd`, `internal/http/router.go`, `internal/http/handlers/matches.go`, `internal/http/dto/`, `docs/api.md`; страницы в `web/` | API возвращает согласованный JSON; фронтенд использует тот же контракт. |
| 3. Проверить координатор отдельной утилитой | `../cmd`, `internal/source/coordinator/`, `../testdata` | Получен настоящий матч либо описан результат проверки и выбран импорт демки для первого сквозного сценария. |
| 4. Сохранить матчи в PostgreSQL | `migrations/`, `internal/repository/`, `internal/repository/postgres/`; подключение через `internal/config/config.go` и `../cmd` | Данные переживают перезапуск; повторный импорт не создаёт дубль; запись матча атомарна. |
| 5. Разобрать демку локально | `internal/source/replay/parser.go`, `internal/source/replay/mapper.go`, `internal/domain/`, `../testdata` | Демка преобразуется в общую модель; повреждённый файл возвращает контролируемую ошибку. |
| 6. Добавить загрузку и фоновые задания | `internal/domain/import_job.go`, `internal/http/handlers/imports.go`, `internal/service/imports.go`, `internal/worker/imports.go`, `internal/repository/postgres/import_jobs.go`; форма в `web/` | Импорт из браузера завершается матчем или понятной ошибкой; повторная отправка не создаёт дубль. |
| 7. Сделать статистику группы | `internal/service/statistics.go`, `internal/repository/postgres/players.go`, `internal/http/handlers/players.go`; страницы участников в `web/` | Расчёты совпадают с ручной проверкой, включая смену стороны игроком. |
| 8. Проверить и запустить | `internal/config/`, `internal/http/middleware/`, `../cmd`, `.env.example`, `.gitignore`, `README.md`, сборка `web/` | Участник открывает сайт и добавляет матч с нужными правами; история сохраняется после перезапуска. |

## Как пользоваться документами

1. Выбрать этап в [плане](PROJECT_PLAN.md), прочитать темы и задание.
2. Найти соответствующие пакеты в таблице выше и прочитать их назначение в [структуре](PROJECT_STRUCTURE.md).
3. Создавать только файлы, необходимые для текущего этапа. На первых этапах допустим простой пример без всех слоёв.
4. Проверить критерий готовности из плана перед переходом к следующему этапу.

Бэкенд на Go пишет владелец проекта; фронтенд в `web/` делает Codex. Контракт API и правила расчётов согласуются вместе. Форматы запросов и ответов фиксируются в `docs/api.md` на этапе 2.
