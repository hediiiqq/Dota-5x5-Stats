# Интерфейс доступа администратора

Экран открывается только по прямому адресу `/?view=admin`.
В публичной навигации и на странице матча ссылки на админку и кнопки входа нет.
Публичный просмотр не запрашивает административную сессию.
Права доступа по-прежнему проверяет сервер, а не наличие ссылки в интерфейсе.

Первый этап интерфейса использует готовые маршруты:

- `GET /api/admin/session` — проверка доступа, SteamID64, срок входа и CSRF-токен;
- `GET /auth/steam` — начало входа;
- `POST /api/admin/logout` — выход на этом устройстве;
- `POST /api/admin/logout-all` — отзыв всех своих сессий, включая текущую.

При успешной проверке отображаются ссылка на Steam-профиль по SteamID64,
время истечения входа по часовому поясу устройства и кнопки выхода.
Ник и аватар не выдумываются: текущий ответ сессии их не содержит.
Отдельно показаны состояния отсутствия входа, отказа в правах, загрузки,
ошибки сети/ответа и завершения сессии. Ошибки проверки можно повторить.
Кнопки блокируются на время выхода; CSRF передаётся в заголовке,
при отказе CSRF состояние перечитывается без автоматического повторения POST.

После клика «Войти через Steam» в sessionStorage сохраняется только время
начала перехода. Оно позволяет на возврате callback к `/` восстановить
`/?view=admin`. Метка действует 10 минут и удаляется при использовании.
Cookie, секрет сессии и CSRF-токен в browser storage не сохраняются.
Если sessionStorage недоступен, после входа можно повторно открыть прямой адрес.

Интерфейс добавлен в существующие `index.html`, `history.js` и `styles.css`:
новые Go-маршруты статики не нужны. Аккаунты импортера, задания и демки
не входят в этот этап и пока не показаны как действующие функции.

Проверка 25.10.2026: 8 новых проверок интерфейса сессии, существующий набор
фронтенда и реальный headless Edge на тестовом локальном API. Браузерные сценарии:
публичная страница без кнопки и запросов сессии, размеры 1440/768/390,
оба выхода, возврат после имитации Steam redirect, отказ в правах, ошибка API,
отсутствие токена в тексте и отсутствие JS-исключений.
Проверки интерфейса не используют реальные Steam-сессии или секреты из `.env`.
Работа нового интерфейса на VPS проверяется после его деплоя.

## Управление плашками

После проверки сессии экран `/?view=admin` показывает редактор плашек и управление
сессиями. Редактор использует [контракт плашек](api-admin-notices.md): список,
создание POST, изменение PUT и удаление DELETE. Административный список загружается
только после подтверждения доступа. На публичных страницах административные API
не вызываются; ссылки на админку в меню нет.

Форма содержит только текст. Дата при необходимости вписывается в него вручную.
Счётчик считает Unicode-символы после обрезки пробелов; допустимо 1–500 символов.
Текст не трактуется как HTML. Изменение заполняет эту же форму и показывает отмену;
удаление требует подтверждения внутри строки. Новые записи показываются первыми.

На время запроса действия блокируются. При отказе сервера введённый текст остаётся
в форме. При сетевой ошибке записи интерфейс не утверждает, что изменение выполнено:
сначала предлагает обновить список и проверить фактический результат. POST/PUT/DELETE
автоматически не повторяются. Ошибка CSRF блокирует запись до проверки доступа;
истечение сессии убирает редактор и предлагает вход. Черновики не сохраняются
в localStorage или sessionStorage и теряются после перезагрузки или повторного входа.

На главной и странице матча статическая HTML-плашка заменена общим GET /api/notices.
Пустой список скрывает область объявлений. Ошибка загрузки показывает повторную
попытку без восстановления старого текста. Изменения видны после обновления страницы.
Старое объявление нужно при необходимости заново опубликовать через редактор;
миграция его не создаёт.

Код размещён в существующих common.js, history.js и match.js, новые маршруты статики
не требуются. Серверный Go-код и конфигурация окружения на этом этапе не менялись.

Проверка 26.10.2026: все 117 тестов фронтенда проходят. Добавлены сценарии редактора
и публичных плашек: CRUD, Unicode и большие ID, обычный текст вместо HTML,
ошибки записи с сохранением черновика, защита от повторной отправки, CSRF и истечение
сессии. Реальный headless Edge с локальным тестовым API проверил CRUD, обе публичные
страницы и размеры 1440/768/390. Проверка интерфейса на VPS выполняется после деплоя.
