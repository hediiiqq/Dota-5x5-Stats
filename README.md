# Dota Stats

Учебный проект на Go для статистики приватных матчей Dota 2 своей группы игроков.
CLI-импортер получает матчи через Steam и Dota 2 Game Coordinator и сохраняет их в PostgreSQL. HTTP API читает сохранённые матчи из базы; для просмотра истории повторный вход в Steam не требуется.

## Требования

- Go 1.27 или новее — версия указана в `go.mod`.
- PostgreSQL и созданная база данных для проекта.
- SQL-консоль GoLand, pgAdmin или `psql` для применения миграций.
- Для импорта: два Steam-аккаунта из текущей конфигурации, Steam Guard и доступ к сети Steam.

Все команды выполняются из корня репозитория.

## Настройка

Установите зависимости:

```sh
go mod download
```

Скопируйте `.env.example` в `.env`. В PowerShell:

```powershell
Copy-Item .env.example .env
```

Если `.env` уже существует, отредактируйте его, сохранив текущие настройки.

| Переменная | Назначение |
| --- | --- |
| `DB_URL` | Подключение к PostgreSQL; требуется серверу и импортеру |
| `STEAM_WEB_API_KEY` | Необязательный Steam Web API key для загрузки аватарок игроков |
| `ACCOUNT1_USERNAME` | Логин первого Steam-аккаунта для импорта |
| `ACCOUNT1_PASSWORD` | Пароль первого Steam-аккаунта |
| `ACCOUNT2_USERNAME` | Логин второго Steam-аккаунта для импорта |
| `ACCOUNT2_PASSWORD` | Пароль второго Steam-аккаунта |

Формат `DB_URL`: `postgres://USER:PASSWORD@HOST:5432/DATABASE?sslmode=disable`. Замените заполнители своими значениями. Специальные символы в логине и пароле нужно кодировать для URL. `sslmode=disable` подходит для локальной разработки; для удалённой базы используйте параметры TLS её администратора.

Конфигурация автоматически читает `.env`. Переменные окружения процесса имеют приоритет. Для запуска только API достаточно `DB_URL`.

`.env`, `ACCOUNT1_TOKEN.txt` и `ACCOUNT2_TOKEN.txt` исключены через `.gitignore`. В `.env.example` значения оставлены пустыми.

## Миграции PostgreSQL

Создайте базу и подключитесь к ней через SQL-консоль. Для новой базы выполните содержимое файлов по порядку:

1. `migrations/001_initial.up.sql` — таблица `matches`, уникальный Dota ID и исходные данные в JSONB.
2. `migrations/002_initial.up.sql` — таблица участников `match_players`.
3. `migrations/003_initial.up.sql` — таблица прогресса синхронизации `gc_sync_state`.

Пример для `psql`: замените `HOST`, `USER` и `DATABASE`, пароль вводится по запросу.

```sh
psql -h HOST -U USER -d DATABASE -W -v ON_ERROR_STOP=1 -1 -f migrations/001_initial.up.sql
psql -h HOST -U USER -d DATABASE -W -v ON_ERROR_STOP=1 -1 -f migrations/002_initial.up.sql
psql -h HOST -U USER -d DATABASE -W -v ON_ERROR_STOP=1 -1 -f migrations/003_initial.up.sql
```

Переходите к следующему файлу только после успешного выполнения предыдущего. Приложение не применяет миграции автоматически и не ведёт таблицу их версий. В существующей базе применяйте только ещё не выполненные миграции: повторный запуск этих файлов вызовет ошибку создания таблиц.

Файлы `*.down.sql` удаляют соответствующие таблицы и данные; для обычного запуска они не нужны.

## Запуск HTTP API

После настройки `DB_URL` и применения миграций:

```sh
go run ./cmd/server
```

Сервер слушает порт `8080` на всех доступных сетевых интерфейсах. Откройте [сайт с историей матчей](http://localhost:8080/), [проверку сервера](http://localhost:8080/api/health) или [JSON истории матчей](http://localhost:8080/api/matches).

### Веб-интерфейс

Фронтенд проекта (HTML, CSS и JavaScript в `web/`) создан нейросетью.

История на `/` показывает дату, Dota ID, победителя и длительность, по 20 матчей на странице. Кнопка «Открыть» ведёт на `/match?id=…&offset=…`: здесь доступны таблицы Radiant и Dire с игроками, названиями героев, K/D/A, GPM, XPM и уроном героям. Возврат к истории сохраняет страницу.

Дата отображается в часовом поясе браузера, неизвестные показатели — как `—`. Mapper добавляет к `hero_id` поле `hero_name` из локального справочника `internal/http/dto/heroes.go`, полученного из [данных официального сайта Dota 2](https://www.dota2.com/datafeed/herolist?language=english). При неизвестном ID имя равно `null`, а интерфейс показывает «Герой #ID»; при отсутствующем ID — `—`. Справочник не требует сетевых запросов при просмотре матчей; при появлении новых героев его нужно обновить. Для просмотра нужен JavaScript. Подключение Steam требуется только для импорта.

На странице матча доступны логотипы команд, если в API есть `radiant_team_logo_url` или `dire_team_logo_url`. Account ID игрока открывает Steam-профиль в новой вкладке. В истории переход к матчу выделен отдельной кнопкой.

Рядом с именем героя отображается мини-иконка 32×32 со Steam CDN: mapper добавляет `hero_icon_url` по внутреннему имени из того же локального справочника. API key для иконок не нужен. Если иконка недоступна, имя остаётся на месте без сломанной картинки.

В шапке матча отображается режим игры (`game_mode_name` по исходному `gameMode`), а после сборок — пики и баны Radiant и Dire с именами и иконками героев. Порядок внутри каждой группы соответствует исходному массиву. Если драфт отсутствует, это указано явно; неизвестные стороны и типы выбора показаны отдельно. Неизвестный код режима отображается как «Режим #ID», отсутствующий — как `—`. Нового импорта для ранее сохранённых матчей с `gameMode` и `picksBans` в `raw_data` не требуется.

Карточка матча оформлена как компактная таблица: портреты и уровни героев, игроки, K/D/A, общая ценность, добивания/denies, золото/опыт в минуту, урон героям/строениям, лечение и инвентарь. Внизу — суммы по командам; если у участника нет показателя, соответствующая сумма остаётся неизвестной. Цветные полосы сравнивают общую ценность игроков, а строки итогов — общую ценность команд.

Под таблицей находятся «Сборки» в две колонки, а затем пики и баны. Сборки показывают предметы на конец матча, рюкзак и дополнительные слоты. Названия и внутренние имена предметов хранятся в `web/assets/items.js` из [официального списка Dota 2](https://www.dota2.com/datafeed/itemlist?language=english); картинки загружаются со Steam CDN без ключа. Нулевой ID — пустой слот, отсутствие данных — `?`, неизвестный предмет сохраняет свой ID в подсказке.

Файлы `web/assets/abilities.js` и `web/assets/skill-build.js` подготовлены для будущего отображения прокачки, но пока не подключены к странице. Получение истории, её сохранение и поля Go API реализует владелец проекта.

Для настоящих аватарок добавьте свой Steam Web API key в `STEAM_WEB_API_KEY` внутри `.env` и перезапустите сервер. Ключ используется только сервером для [GetPlayerSummaries](https://partner.steamgames.com/doc/webapi/ISteamUser#GetPlayerSummaries), в браузер не передаётся. Запросы группируются по игрокам матча; URL аватарок кэшируются в памяти на 6 часов, отсутствующие ответы — на минуту. Необязательный `GET /api/players/avatars?account_ids=123,456` принимает до 10 положительных 32-битных Account ID и возвращает `{"avatars":{"123":"https://…"}}`. Без ключа, при недоступности Steam или ошибке изображения показываются инициалы; статистика загружается независимо. Авторизация Steam и Game Coordinator для аватарок не используются.

HTML, CSS и JavaScript находятся в `web/` и раздаются этим же Go-сервером. Отдельная установка npm, сборка фронтенда и отдельный порт не нужны. Запускайте сервер из корня проекта, чтобы файлы `web/` были доступны.

| Метод | Маршрут | Результат |
| --- | --- | --- |
| GET | `/api/health` | `{"status":"ok"}`; проверка HTTP-обработчика без отдельного запроса к БД |
| GET | `/api/matches?limit=20&offset=0` | Массив полных матчей, от новых к старым; пустая история — `[]` |
| GET | `/api/matches/{id}` | Один матч по внутреннему ID из списка |

`limit` по умолчанию равен `20`, допустимы значения от `1` до `100`. `offset` по умолчанию равен `0` и должен быть неотрицательным целым числом. Следующая страница при размере `20`: `/api/matches?limit=20&offset=20`.

Поле `id` — внутренний числовой идентификатор PostgreSQL. Именно его нужно подставлять в `/api/matches/{id}`. Поле `dota_match_id` — отдельный внешний идентификатор Dota 2, передаваемый строкой.

Время начала возвращается в UTC, длительность — в секундах. Отсутствующие показатели представлены как `null`, известный ноль — как `0`. `winner` равен `radiant`, `dire` или `null`, если исход неизвестен. Ответ содержит игроков, доступные названия и логотипы команд, пики и баны.

Ошибки возвращаются в JSON с объектом `error`, содержащим `code` и `message`:

| Статус | Код | Причина |
| --- | --- | --- |
| 400 | `invalid_match_id` | Неположительный, нечисловой ID или переполнение int64 |
| 400 | `invalid_limit` | Неверное значение `limit` |
| 400 | `invalid_offset` | Неверное значение `offset` |
| 404 | `match_not_found` | Матч с указанным внутренним ID отсутствует |
| 404 | `not_found` | Неизвестный маршрут |
| 405 | `method_not_allowed` | Неподдерживаемый метод известного маршрута; `Allow: GET, HEAD` |
| 500 | `internal_error` | Ошибка чтения БД или обработки сохранённых данных |

GET-маршруты также поддерживают HEAD.

## Запуск импорта из Steam

Заполните `DB_URL` и переменные обоих Steam-аккаунтов, примените все три миграции, затем выполните:

```sh
go run ./cmd/gc-check
```

При первом входе подтвердите авторизацию в мобильном приложении Steam. Импортер сохраняет токены в `ACCOUNT1_TOKEN.txt` и `ACCOUNT2_TOKEN.txt` для следующих запусков. Общий таймаут работы каждого аккаунта — 15 минут, авторизации — 180 секунд.

Аккаунты обрабатываются параллельно. Импортер выбирает приватные лобби с `lobby_type=1` и режимами `game_mode=2` или `16`, получает подробности и сохраняет матчи с десятью участниками. Матч и участники записываются одной транзакцией; повторная запись существующего Dota ID не создаёт дубль.

По умолчанию нижняя граница Dota ID — `6000000000`. Сохранённый прогресс аккаунта используется при последующих запусках. Доступны флаги:

```sh
go run ./cmd/gc-check -min-match-id=8000000000
go run ./cmd/gc-check -full-history -min-match-id=6000000000
```

`-full-history` игнорирует сохранённую границу прогресса и просматривает историю до `-min-match-id`. Уже сохранённые матчи по-прежнему пропускаются. После импорта они доступны через HTTP API.

## Учебная версия

```sh
go run .
```

Эта команда запускает старую учебную версию из корневого `main.go`: она читает `testdata/match.json` и хранит один матч с ID `1` в памяти. Основной сервер PostgreSQL запускается через `go run ./cmd/server`. Обе версии используют порт `8080`, поэтому одновременно на одном адресе их запускать нельзя.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `cmd/server/` | HTTP API над PostgreSQL |
| `cmd/gc-check/` | CLI-импорт через Steam и Dota 2 GC |
| `internal/config/` | Конфигурация и переменные окружения |
| `internal/http/` | Роутер, обработчики, DTO и преобразование данных |
| `internal/repository/postgres/` | Матчи, участники и прогресс синхронизации |
| `internal/source/coordinator/` | Работа со Steam и Dota 2 GC |
| `migrations/` | SQL-миграции |
| `testdata/` | Локальные примеры матчей |
| `docs/` | Контракт API и планы |
| `web/` | История и страница матча, стили и JavaScript без отдельной сборки |
| `main.go` | Старая учебная версия без PostgreSQL |
| `.env.example` | Пустой шаблон конфигурации |
